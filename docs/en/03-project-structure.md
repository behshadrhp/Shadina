## Package responsibilities

| Package | Imports (internal) | Owns | Does not own |
|---|---|---|---|
| `cmd/api` | `docs`, `internal/auth`, `consts`, `db`, `dto`, `env`, `response`, `storage`, `utils` | HTTP routing, middleware, handlers, application wiring | Domain services, transactions, response DTOs beyond health |
| `cmd/seed` | `internal/db`, `internal/env`, `internal/storage` | Executable seed entry point | Schema creation (migrations own that) |
| `docs` | none internal | Generated Swagger template and runtime metadata | Handwritten API docs |
| `internal/auth` | none internal | Token interface + HS256 implementation | User lookup, authorization policy, password hashing |
| `internal/consts` | none internal | Timeouts, sentinel error, context key | Configuration loading |
| `internal/db` | `internal/consts`, `internal/storage` | DB connection, pool setup, seed generation | Query methods, migrations |
| `internal/dto` | none internal | Request payloads, health response | Response models for users/posts |
| `internal/env` | none internal | Env helpers | Validation of config values |
| `internal/response` | none internal | JSON envelope/status helpers | Error classification/logging |
| `internal/storage` | `internal/consts` | SQL, persistence structs, bcrypt password methods, feed pagination parsing | HTTP routing, authorization |
| `internal/utils` | none internal | JSON body handling, global validator | Error mapping |

## Entry points and executables

| Executable | Build command | Notes |
|---|---|---|
| API | `go build -o /tmp/shadina-api ./cmd/api` | The only long-running process. |
| Seed | `go run ./cmd/seed` | Requires a migrated database. Not idempotent. |
| Migration | external `migrate` CLI | `go build ./cmd/migrate` fails: `no Go files`. |
| Air dev runner | `air` | `.air.toml` builds `./cmd/api/*.go`, but `pre_cmd` runs `make gen-docs`, which currently fails. |
| Tracked binary | `bin/main` | Already committed; may be stale relative to source. Prefer rebuilding to a temporary path. |

## Generated versus handwritten files

| Generated | Handwritten |
|---|---|
| `docs/docs.go` | `cmd/**/*.go` |
| `docs/swagger.json` | `internal/**/*.go` |
| `docs/swagger.yaml` | `cmd/migrate/migrations/*.sql` |
| `bin/main` (build artifact) | `makefile`, `docker-compose.yaml`, configs |
| `logs/*` at runtime | `README.md`, `LICENSE`, `scripts/init_db.sql` |

`docs.go` starts with the standard swaggo header: `Code generated by swaggo/swag. DO NOT EDIT`.
Do not hand-edit generated Swagger files; fix annotations/DTOs and regenerate (currently blocked, see below).

## File-level observations

- `cmd/api/uesrs.go` is a filename typo; the package and handlers are valid.
- `cmd/api/auth.go` mixes registration and token handlers; there is no `internal/service` package.
- `internal/storage/pagination.go` imports `net/http` and parses query strings; the storage package is not
  purely persistence.
- `internal/db/seed.go` imports `internal/storage`; DB bootstrap and fixture generation are coupled.
- `internal/dto` has no response structs for `User`, `Post`, or `Comment`; storage structs are serialized
  directly by handlers.
- `docs/swagger.json` and `docs/swagger.yaml` are semantically consistent with each other (verified by
  parsing and comparing keys/values), but they are stale relative to handlers.
- `scripts/init_db.sql` uses `CREATE DATABASE IF NOT EXISTS`, which PostgreSQL does not support, and it
  creates an extension before selecting a database. It is not referenced by Compose or the makefile.
- `web/` is empty; there is no frontend build or static asset pipeline.
- `bin/main` is tracked despite being a build artifact. `.gitignore` does not exclude `bin/`.
- `logs/` and `tmp/` are ignored; `.env` is ignored. `.example.env` is tracked but incomplete for auth.

## Missing structure

The following are absent from the repository:

- `cmd/migrate/main.go` (migration CLI is external)
- `Dockerfile` / application image
- `.github/`, `.gitlab-ci.yml`, or any CI configuration
- `*_test.go`, mocks, fixtures, or testcontainers setup
- OpenAPI/contract tests
- `internal/service`, `internal/domain`, or repository-per-entity packages
- Metrics/tracing configuration
- `.golangci.yml` (golangci-lint uses defaults)
